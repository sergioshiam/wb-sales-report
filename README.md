# WB Sales Report

Сервис на **FastAPI**, который забирает продажи и остатки продавца из официального API **Wildberries**, сохраняет их в **PostgreSQL** и отдаёт отчёт по артикулам: продажи, возвраты, выручка, сумма к перечислению, остатки на складах и на сколько дней их хватит.

Отвечает на вопросы, которые продавец задаёт каждый день:
- какой товар продаётся и сколько денег он принёс за период;
- где высокий процент возвратов;
- что скоро закончится на складе (статус **«дефицит»**);
- что лежит на складе и не продаётся (статус **«нет продаж»**).

Без токена продавца сервис работает в **демо-режиме** на сгенерированных данных (бренд и товары вымышленные), поэтому его можно запустить и проверить сразу.

## Стек

Python 3.12 · FastAPI · SQLAlchemy 2 · PostgreSQL 16 (psycopg 3) · httpx · pytest · Docker / docker compose

## Быстрый старт

### Через Docker

```bash
cp .env.example .env        # при желании вписать WB_TOKEN
docker compose up --build
```

Документация API с кнопками «попробовать» откроется на http://localhost:8000/docs

### Без Docker (SQLite вместо PostgreSQL)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### Порядок работы

1. `POST /sync` загружает данные из WB (или демо-данные) в базу.
2. `GET /report` возвращает отчёт по всем артикулам.

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | Проверка, что сервис жив, и режим работы (`demo` / `wb_api`) |
| POST | `/sync?date_from=2026-10-01` | Загрузка продаж с указанной даты и текущих остатков. По умолчанию за последние 30 дней |
| GET | `/report?days=30` | Отчёт по всем артикулам за период (1–90 дней) |
| GET | `/report/{nm_id}` | Отчёт по одному артикулу WB |

Пример строки отчёта:

```json
{
  "nm_id": 210000102,
  "supplier_article": "DEMO-LEG-02",
  "sold_qty": 90,
  "returned_qty": 3,
  "net_qty": 87,
  "return_rate_pct": 3.3,
  "revenue": 132505.0,
  "for_pay": 105861.6,
  "avg_daily_sales": 2.9,
  "stock_qty": 27,
  "days_of_stock": 9.3,
  "status": "дефицит"
}
```

## Работа с API Wildberries

| Данные | Метод WB | Ограничение |
|---|---|---|
| Продажи и возвраты | `GET statistics-api.wildberries.ru/api/v1/supplier/sales` | 1 запрос в минуту |
| Остатки на складах WB | `POST seller-analytics-api.wildberries.ru/api/analytics/v1/stocks-report/wb-warehouses` | 3 запроса в минуту |

Что учтено в клиенте (`app/wb_client.py`):
- **Пагинация продаж.** WB отдаёт данные порциями. Следующая порция запрашивается с `dateFrom` = `lastChangeDate` последней строки, пока не придёт пустой ответ.
- **Пагинация остатков** через `limit` / `offset`; ответ `204` означает «данных нет».
- **Лимиты.** Между запросами выдерживается пауза. При ответе `429` клиент ждёт столько секунд, сколько указано в заголовке `X-Ratelimit-Retry`, и повторяет запрос.
- **Актуальный метод остатков.** Старый `GET /api/v1/supplier/stocks` WB отключил в июне 2026 года, поэтому используется новый отчёт из раздела «Аналитика».

Токен создаётся в личном кабинете продавца: *Профиль → Интеграции по API*, категории «Статистика» и «Аналитика», режим «Только чтение».

## Логика расчётов (`app/reports.py`)

- Продажа и возврат различаются по `saleID`: `S…` означает продажу, `R…` означает возврат.
- **Выручка** = сумма продаж по цене покупателя (`finishedPrice`) минус возвраты. **К перечислению** (`forPay`) считается так же. Знак суммы возврата не важен: берётся модуль.
- **Процент возвратов** = возвраты / продажи × 100.
- **Средние продажи в день** = (продажи − возвраты) / число дней периода.
- **Дней запаса** = остаток на складах / средние продажи в день.
- **Статус:** «дефицит», если запаса меньше чем на 14 дней; «нет продаж», если товар есть на складе, а продаж за период нет; иначе «норма».
- Повторная синхронизация не создаёт дублей: строка продажи определяется парой `srid` + `saleID`. Остатки при каждой загрузке заменяются свежим снимком.

## Тесты

```bash
pytest -q
```

- расчёты отчёта на данных с заранее известным ответом;
- клиент WB с подменой ответов сервера: пагинация, заголовок авторизации, повтор после `429`, ответ `204`, ошибка `401`;
- сквозной сценарий через HTTP: `/sync` → `/report`.
